2026-11-03: Live server vs spec/docs, from the first spikes (details in docs/PROTOCOL_NOTES.md):
- `update_agent_detail` with the agent's own key is refused (403 "An agent can't change its own settings"). Addressing is set by the owner: `PUT /gateway/agents/{id}/addressing-policy` (`{"policy": null}` = anyone), via scripts/gateway.py. Part 2's `make register` needs that owner step for keymaster and sentinel.
- New agents default to `addressing_policy` owner + owner_agents (matches the 0.31 changelog, not the older docs line "answers its owner and nobody else").
- `post_message` takes `body` and `thread_id`; `POST /agents/{id}/message` takes `room_id` and `content`. Threads are keyed by the root message's `event_id` (`sw_…`).
- There is no list-documents op: document metadata comes from `connect_to_room`, content from `load_internal_documents {ids}`. `update_room_document` replaces fields, so the append-only lease-ledger is rewritten in full on each change.
- Registration auto-adds the agent to the bundled Mattermost rooms and Switch posts a greeting in its name.
- Cursors are opaque large ints (a gap returned resumed_at = 2^53 − 2^32); store, never compute. connection_state carries an undocumented `position` map and protocol 9.
- An agent's own posts are not echoed on its socket.
- 18 ops exist that the docs catalog omits (create_agent, templates, machines, get_my_context, …); none are needed yet.

2026-11-04: Part 2 (Switch client and keymaster) design choices:
- One WebSocket connection per room. `connect_to_room` replaces a connection's subscription, so each room gets its own `RoomConnection` (opened with `scope=all&filter=all&rooms=<room>`, then claimed). Each keeps its cursor in `.state/<agent>.<room>.cursor.json`, written at most every 2 s and on stop. Pings are answered by the reader before any handler runs, so a slow handler never delays a pong. `taken_over` and `closed` end the room for good, `gap` moves the cursor to `resumed_at` and flags the next event `after_gap`, and three failed claims in a row end the room as ROOM_LOST instead of retrying forever.
- New rooms are found by polling `list_rooms` every 30 s (an invitation sends no frame). An agent learns its own message `sender` id from its `room_join` entry in `read_context`; `make register` also writes it to `.env` as `LEASEDESK_<NAME>_ID`.
- Verdicts count only from `LEASEDESK_SENTINEL_ID` outside dev mode. A Discord display name can be copied by anyone, so a name match never grants anything; it is only used to refuse (an approval from a sender named like an agent is refused).
- Replies about a lease (approval request, receipt, expiry, revoke) go into the lease's own thread, rooted at the submit message. Refusals and status replies go under the command that asked.
- AWS caps a user's inline policies at 2,048 non-whitespace characters in total, so keymaster checks the new policy plus the user's other inline policies at confirm (CANCELLED with a plain message) and again before writing (FAILED, nothing written).
- Mock mode runs a moto server (`make moto`) with IAM auth switched on after seeding, so keymaster and lease-demo-dev use real (mock) keys and the access check really flips. moto ignores `aws:CurrentTime` conditions (and StringLike), so in mock mode access ends because keymaster deletes the policy at expiry; in real mode AWS also ends it at `DateLessThan` on its own. moto authorizes IAM calls against resource `*`, so the mock keymaster user's IAM permissions use `*` instead of the real `/leasedesk/` user path.
- The access policy is read only from a document no agent created (`created_by_agent_id` null), searched across every room keymaster is in; two different documents with that name are refused. The last good policy stays in force when a reload fails.
- keymaster tries `assume_role("executor")` in each room and retries every 60 s; rooms have no roles until Part 4, so this is logged and not fatal.
- A stop (SIGINT/SIGTERM) revokes nothing: AWS still ends active leases at expiry, and the next start reconciles and catches up from SQLite.

2026-11-06: Part 3 (sentinel) — parliament and the rule sources:
- parliament 1.6.4 API used: `analyze_policy_string(json_str)` returns a Policy whose `.findings` carry `issue`, `detail` and `location` (severity, title and description are only filled by `parliament.enhance_finding`); `parliament.iam_definition` (AWS service authorization data bundled with parliament: 455 services, each privilege with `access_level` List / Read / Write / Permissions management / Tagging) for wildcard expansion and access levels. sentinel expands wildcards itself from `iam_definition` (lower-cased, `fnmatch`), because `expand_action` raises on unknown names. Lint runs once per statement (a one-statement policy built from keymaster's own `render_policy` with a fixed 2030-01-01 window), so each parliament finding maps to a sid. Importing parliament warns (pkg_resources deprecation, invalid escapes); `leasedesk/sentinel/actions.py` and `analyzers/lint.py` import it inside `warnings.catch_warnings()`. One analysis takes about 1 ms. parliament's data is from 2023, so a newer AWS action is BLOCKed as unknown; that fails closed. The community auditors are not used (sentinel's own escalation data replaces them).
- parliament finding mapping: MALFORMED_JSON, MALFORMED, EXCEPTION, UNKNOWN_ACTION, UNKNOWN_PREFIX, INVALID_ARN → BLOCK; RESOURCE_MISMATCH and condition-type issues → MEDIUM with parliament's text as the fix; RESOURCE_STAR / RESOURCE_EFFECTIVELY_STAR are left to sentinel's scope rule (HIGH); the rest → LOW.
- `s3:DeletePublicAccessBlock` is not an IAM action (parliament doesn't know it; the DeletePublicAccessBlock API is authorised by `s3:PutBucketPublicAccessBlock`). The tamper list keeps the name from the brief and adds `s3:PutBucketPublicAccessBlock` and `s3:PutAccountPublicAccessBlock`.
- Escalation paths (`leasedesk/sentinel/data/escalation_paths.yaml`, 31 entries) cite Rhino Security Labs' 21 methods (the page has no per-method anchors, so the method number is in each name and the link goes to the matching hackingthe.cloud anchor), Rhino's part 2 for SageMaker and Lambda layers, and hackingthe.cloud for ECS, SSM SendCommand and Session Manager, Glue jobs and permission boundaries. None of the listed sources covers CodeBuild; that entry cites the AWS CodeBuild guide, which warns that a project's service role "can unintentionally escalate a user's permissions". The brief's ECS (RegisterTaskDefinition + RunTask) and SageMaker (CreateNotebookInstance) sets are kept as given; the sources also describe PassRole + ecs:RunTask and add CreatePresignedNotebookInstanceUrl.
- moto has no Access Analyzer, so ValidatePolicy and CheckAccessNotGranted are tested with botocore's Stubber. sentinel's sandbox policy (scripts/aws/policies/sentinel-policy.json) now also allows `access-analyzer:CheckAccessNotGranted`; the paid check still only runs with `LEASEDESK_ENABLE_PAID_CHECKS=true` in real mode.

2026-11-06: Part 3 (sentinel) design choices:
- Trust: only a review request whose `sender` is `LEASEDESK_KEYMASTER_ID` gets a `verdict` block, even in dev mode (a display name can be copied). Anything else, and every `@sentinel check`, gets an `advisory` block that keymaster never counts. keymaster checks a verdict's sender before parsing it and then requires the `proposal_hash` of the lease it holds.
- sentinel reads proposals leniently (`ProposalView`), so a malformed or over-broad lease is judged and explained instead of bounced; keymaster's strict schema is unchanged.
- A corrected lease is offered only when every fix is mechanical, and only if its re-review has no BLOCK or HIGH finding and a lower risk. It says what it changed. Mechanical changes: `s3:*` split into `s3:GetObject` (plus `s3:PutObject` when the summary says the task writes) and `s3:ListBucket`, `bucket/*` narrowed to the folder the lease or summary names, an `s3:prefix` condition, dropped tamper/forbidden/permissions-management/escalation actions, and 60 minutes. A crash in the fixer drops the suggestion, never the verdict.
- Text that came from a proposal is cleaned in every sentinel message (backtick → `'`, `@` → `(at)`; JSON blocks escape them), so an echoed "@keymaster approve" or a stray fence can't reach keymaster's parser.
- Verdict messages fit Discord's 2,000 characters: at most 4 findings in the summary, findings in the block clipped (detail 160, fix 120, no reference) with a `more-findings` pointer; `@sentinel explain <id>` has everything and the arithmetic. Reviews are stored append-only in `.state/sentinel.db` (mode 600); advisory ids are `C-<8 hex of the proposal hash>`, and `explain LS-n` prefers the gating review.
- Delivery to another agent tries roles, then names, then a plain `@name` post (`SwitchAgent.deliver`). Rooms have no roles yet, so names is what works.
- Rate limit: 10 requests a minute per sender, one "slow down" reply, keymaster exempt. Results are cached by proposal hash plus the context (policy and catalog hashes, AWS mode); a real-mode result whose AWS check was skipped isn't cached.
- `make up` runs both agents under `scripts/demo/supervise.py`: a crash restarts after 1 s, doubling to 30 s; exit codes 0, 2, 3 and 4 (stopped, config refused, taken over, key rejected) are final.
- structlog no longer caches loggers on first use: a module logger first used under the CLI's WARNING level kept that level for the rest of the process.

2026-11-06: Part 3 final review (a fresh reviewer read the whole change; no Critical findings). Fixed, each with a test that failed first:
- keymaster repeats proposal text (summary, hint, actions, resources) in its own messages, so a `review` block hidden in a resource string reached sentinel as "from keymaster" and got a gating verdict (keymaster's hash check still refused it, but `explain` showed the forged review). sentinel now gives a verdict only when the message opens with keymaster's own "LS-n · confirmed by" line naming the block's lease, and keymaster echoes proposal text on one line with backticks and `@` cleaned.
- Splitting `s3:*` for a corrected lease dropped the statement's conditions, which could widen access. Each split statement now keeps them all, and the test helper checks it.
- A crown jewel listed by its exact bucket ARN now covers the bucket's objects (it already did for the paid check).
- parliament's condition-mismatch remark is one finding per statement (a `s3:*` statement with `s3:prefix` gave 161), and `explain` shows at most 15 findings, so one request can't flood the room.
- With `LEASEDESK_ENABLE_PAID_CHECKS=true`, the paid CheckAccessNotGranted call now runs only for keymaster's review requests, not for anyone's `@sentinel check`.
